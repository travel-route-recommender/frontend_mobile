# DURI Analysis + Suggestion Preview Final Report

## Before

기존 분석 화면은 `분석 / 개선 제안` 탭과 긴 검사 목록을 중심으로 구성되어, 사용자가 가장 먼저 알아야 할 결론과 다음 행동이 첫 화면 아래에 묻혔다. 제안 미리보기 역시 Before/After 원문이 먼저 노출되어 변경 내용과 적용 버튼을 빠르게 파악하기 어려웠다.

작업 전 기준 화면은 로컬 시각 QA에 사용했으며 장기 저장소 산출물에는 포함하지 않는다.

## Analysis IA

분석 화면의 우선순위를 다음처럼 재구성했다.

1. DURI의 한 문장 결론과 대표 개선 포인트
2. 실제 분석 결과로 만든 네 개의 핵심 수치
3. 제안이 있으면 즉시 보이는 주요 CTA
4. 실제 근거가 있는 강점과 우선 개선 항목
5. 지표, 전체 검사, 일정별 근거, 선호 근거의 점진적 공개

긴 검사 결과와 근거는 삭제하지 않고 disclosure 안으로 이동했다. 사용자는 먼저 판단하고, 필요할 때 세부 근거를 펼칠 수 있다.

## Suggestion IA

미리보기는 `무엇이 바뀌는가 → 왜 바꾸는가 → 어떤 영향이 있는가 → 어느 일정에 적용되는가 → 전체 전후 비교` 순서로 구성했다. 적용과 취소는 스크롤 위치와 무관하게 하단 고정 영역에 유지된다.

## Character

두 화면 모두 프로젝트의 공식 기획 이미지 `design/image/duri_analysis_planning.png`를 직접 import하고 `contain` 방식으로 사용한다. 임의 크롭, 재가공, 별도 복사본은 만들지 않았으며 화면당 한 번만 배치했다.

## Design Foundation

기존 디자인 파운데이션을 유지했다. 흰색 페이지 바탕, 딥 네이비 본문, 파란색 주요 행동, 라벤더 요약, 민트 강점, 피치 개선 항목을 사용했다. 기본 좌우 여백은 20px, 카드 모서리는 18–22px 범위로 통일했다.

## Actual Data

레퍼런스의 예시 문구나 수치를 하드코딩하지 않았다. 요약, 통계, 문제, 변경 내용, 영향 일정은 현재 분석 세션과 제안 결과로 만든 ViewModel을 통해 표시된다.

강점도 실제 사실이 있을 때만 노출한다. 현재 규칙은 충돌 없음, 후보 활용, 전체 이동 경로 확인 완료처럼 분석 결과에서 직접 확인 가능한 항목에 한정했다. 확인되지 않은 선호 효과나 품질 개선을 추정하지 않는다.

## Reanalysis Error

재분석 실패 시 기존 성공 결과는 유지하고, 사용자가 현재 상태와 재시도 가능 여부를 알 수 있도록 화면 상단에 실패 배너를 표시한다. 분석 결과가 없는 최초 실패 상태와 기존 결과가 있는 재분석 실패 상태를 모두 처리한다.

## Stale

기존 canonical fingerprint 생성·비교 경로는 변경하지 않았다. 일정 또는 관련 입력이 바뀌어 fingerprint가 달라지면 분석 화면과 제안 화면 모두 오래된 결과임을 명시하고 재분석을 안내한다. 기술적인 fingerprint 값은 사용자 문구에 노출하지 않는다.

## Apply

제안 생성, 공유 미리보기, atomic apply 흐름은 기존 엔진과 저장소를 그대로 사용한다. 확인 모달에는 실제 변경 개수와 영향을 받는 날짜를 표시하고, 전체 변경이 한 번에 적용된다는 점을 일반 문장으로 설명한다. 읽기 전용 또는 오래된 제안은 적용 버튼을 비활성화하고 이유를 함께 보여 준다.

브라우저 검증에서 취소는 분석 화면으로 돌아가며 일정을 변경하지 않았고, 적용은 워크스페이스로 이동하면서 대상 일정 한 건만 추가했다. 적용 후 입력 변경으로 DURI 결과가 오래된 상태가 되는 것도 확인했다.

## Parallel Development

이번 변경은 DURI 화면·표현 컴포넌트에만 한정했다. 분석 엔진, 제안 엔진, 저장소, fingerprint, workspace 도메인 로직은 수정하지 않았다. 작업 시작 시 존재하던 다른 기능의 변경 파일은 되돌리거나 덮어쓰지 않았다.

## Target Deviations

- 실제 앱의 DURI 경로는 탭 내부의 중첩 상세 화면이므로, 레퍼런스 이미지의 Bottom Navigation을 새로 만들지 않았다.
- 844px 높이의 첫 화면에서도 주요 행동이 보이도록 제안 CTA를 통계 바로 다음에 배치했다.
- 공유·도움말처럼 현재 제품 계약에 없는 행동은 추가하지 않았다.
- 선호 영향이 실제 결과로 확인되지 않으면 효과 문구를 만들지 않는다.
- 공식 캐릭터 이미지는 크롭하지 않고 원본 비율을 유지했다.
- 전체 Before/After 비교는 정보 보존을 위해 남기되 기본 접힘 상태로 제공한다.

## Responsive

360px, 390px, 430px 너비와 844px 높이에서 분석·제안 화면을 각각 검증했다. 모든 경우 `body`와 문서의 `scrollWidth`가 viewport 너비와 같아 수평 오버플로가 없었다. 제안 화면의 고정 footer는 세 너비 모두 780–832px 범위를 유지했고, 본문을 스크롤한 뒤에도 위치가 변하지 않았다.

360px, 390px, 430px 최종 캡처는 로컬 시각 QA에 사용했으며 장기 저장소 산출물에는 포함하지 않는다.

## Remaining Issues

- 분석 엔진이 만드는 일부 한국어 조사 문구(예: 받침에 맞지 않는 `을/를`)는 기존 엔진 출력이며 이번 UI 범위에서 변경하지 않았다.
- 적용 후 Undo는 현재 제품 계약에 없다.
- API 기반 여행에서 DURI를 사용할 수 없는 기존 capability 제한은 그대로다.
- 재분석 실패 분기는 구현·정적 검증했지만, 정상 fixture를 의도적으로 훼손해 브라우저 실패 화면을 만들지는 않았다.
