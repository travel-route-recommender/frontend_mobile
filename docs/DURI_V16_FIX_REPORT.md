인증 검증은 로컬 pending을 유지하면서 전송 객체에 토큰만 포함되는지, 일치하는 ID로 갱신 완료가 가능한지, 기존 재시도/오래된 응답 차단이 유지되는지를 확인한다. 초안 검증은 앞 단계별 교정 위치, 현재 단계 오류, 회원 오류, 교정 후 정상 완료를 확인한다. 실제 배포 서버 로그인·앱 재실행 E2E 검증은 하지 않았다.

사용자 확인: 현재 소스를 실행해 로그인 → 웹 새로고침 또는 앱 재실행 → 보호된 화면/로그아웃을 확인한다. `operationId should not exist`는 더 이상 요청에 의해 발생하지 않아야 한다. 토큰 자체의 만료나 별도 복원 오류까지 해결됐다고 보장하지는 않는다. 초대 화면은 안내 문구·복사 버튼을, 여행방 초안은 앞 단계 오류 안내와 교정 이동을 확인한다. AAB 재빌드·배포·커밋은 수행하지 않았다.

## 첨부 사진의 추가 항목

### 숫자 지역 코드 및 상위 지역 중복

- 여행방의 `37` 같은 지역 코드를 UI의 `jeonbuk`으로 변환했다.
- 숫자 코드와 지역 ID가 섞여 있어도 같은 도로 비교한다.
- 선택 라벨에 `37::all` 대신 지역명을 표시한다.
- 같은 도의 전체/시군구 선택은 중복을 제거하고 다른 도의 선택은 유지한다.
- 관광정보 API의 분류 파라미터나 재시도 정책은 바꾸지 않았다.

### 여행 정보 수정의 완료 버튼

- 사진에는 종료 시각의 HH:mm 형식 오류가 표시돼 있었다. 유효성 검증 자체를 제거하지 않았다.
- 모바일의 종료 시각 입력을 기존 시간 선택 컴포넌트로 바꿨다. 네이티브에서는 시간 선택창을 사용하며 1분 단위를 유지한다.
- 빈 필수 정보가 있거나 다른 입력이 잘못되면 완료 버튼은 계속 비활성화된다.
- 웹에서는 기존 컴포넌트의 HH:mm 텍스트 입력을 사용한다.

### 공유 문서함

- 최신 로컬 백엔드는 목록 `{ data: [...] }`, 업로드 문서 객체, 삭제 `{ success: true }`를 반환한다. `scheduleVersion`/`factsVersion`은 없다.
- 일반 문서 목록과 업로드/삭제 성공 처리를 이 계약에 맞췄다. 버전이 없다는 이유만으로 성공한 업로드를 실패로 표시하지 않는다.
- 문서 ID 중복, 다른 여행방 문서, 다운로드 경로 등 검증은 유지했다.
- 서버가 버전을 보내면 검증하고 보존한다. 임의의 0이나 현재 일정 버전으로 대체하지 않는다.
- **분석용 버전 일관성 검증은 그대로다.** 현재 백엔드에서는 분석용 공유 문서 조회가 여전히 unavailable일 수 있다. 문서를 분석에 안전하게 포함하려면 실제 문서 변경과 연결된 버전 계약을 별도로 맞춰야 한다.
- 사진의 일반 네트워크 오류까지 모두 해결됐다고 단정할 수는 없다. 실제 PDF/이미지 업로드와 다운로드는 기기에서 추가 확인해야 한다.

초대 링크 복사 버튼은 기존 코드에 이미 있어 중복 추가하지 않았다. API 호스트를 사용하는 공유 URL의 외부 브라우저 랜딩/앱 연결은 별도 확인 사항이며, 존재하지 않는 공개 도메인을 임의로 넣지 않았다.

## 사용자 기기 확인

현재 소스를 실행해야 한다. Play에서 설치한 기존 AAB는 소스 수정만으로 바뀌지 않는다.

프로젝트 폴더에서, Android SDK 및 기기가 연결된 환경 기준:

```sh
adb devices
# 개발 빌드가 아직 없다면 한 번 생성·설치
EXPO_PUBLIC_DATA_SOURCE=api npx expo run:android --device
# 이미 현재 네이티브 설정에 맞는 개발 빌드가 설치돼 있다면
EXPO_PUBLIC_DATA_SOURCE=api npx expo start --dev-client --clear
```

두 실행 명령을 동시에 실행할 필요는 없다. WSL에서 `adb devices`에 Windows 에뮬레이터가 나오지 않으면 먼저 Windows/WSL의 ADB 연결을 맞춰야 한다. API 주소는 기기에서 접근 가능한 배포 주소 또는 개발 서버 주소여야 한다. Google/Kakao 로그인 검증에는 해당 네이티브 설정을 포함한 개발 빌드가 필요하다.

확인 순서:

1. 새로 로그인한 상태에서 저장 탭에 들어간다. 2번은 미수정이므로 강제 종료 후 복원 테스트와 분리한다.
2. 홈에서 하트를 누른 후 성공 안내와 저장 탭 반영을 확인한다. 연타, 삭제, 실행 취소도 확인한다.
3. 새 방을 만든 뒤 로그아웃 없이 홈/여행 목록에서 나타나는지 확인한다.
4. 일정 추가 창에서 키보드를 열고 닫고 시트를 늘이고 줄인다. 검색 결과가 0개/1개/여러 개인 경우를 확인한다.
5. 생성 완료 화면에서 API URL이 표시되지 않고 공유·복사가 되는지 확인한다. 다른 기기에서 실제 링크도 열어 본다.
6. 종료 시각을 시간 선택창에서 입력하고 수정 완료를 확인한다.
7. 전북 여행방에서 장소 탐색으로 이동해 지역명이 표시되고 시군구 선택 시 상위 전체 선택이 중복으로 남지 않는지 확인한다.
8. 10MB 이하 PDF/이미지 업로드 → 목록 재조회 → 다운로드 → 삭제를 확인한다.
